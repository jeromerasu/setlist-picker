# BE-002 — V001 baseline migration (13 tables per ADR-006)

**Wave:** 1
**Type:** BE
**Blocked by:** BE-001
**Blocks:** every other BE ticket
**ADR references:** [ADR-006 § 2, § 3, § 6](../../decisions/ADR-006-initial-data-schema.md), [ADR-001](../../decisions/ADR-001-tech-stack.md)

## 1. Problem statement

The schema designed in ADR-006 has zero implementation. Every group/auth/pick/event endpoint reads or writes these tables. This ticket creates the V001 Alembic migration that lands all 13 tables, all indexes from ADR-006 § 3, and the SQLAlchemy 2.0 async session machinery in front of them.

## 2. Actual solution

Set up SQLAlchemy 2.0 (`DeclarativeBase` style) + async engine (`asyncpg` driver) + Alembic. `app/db/session.py` exposes `async_session_maker()` and a `get_db()` FastAPI dependency. `app/db/models/` contains one file per logical group: `user.py`, `group.py`, `member.py`, `device.py`, `event.py`, `stage.py`, `set.py`, `artist.py`, `pick.py`, `artist_cache.py`, `group_activity.py`. UUIDv7 PKs use the `uuid-utils` library's `uuid7()` helper as the column `default`.

Alembic config: async-aware via `run_async_migrations` recipe from SQLAlchemy 2.0 docs. `alembic.ini` reads `sqlalchemy.url` from `DATABASE_URL`. `versions/0001_v001_baseline.py` is **hand-written, not autogenerated** — autogen miscaptures partial-index `WHERE` clauses, JSONB defaults, and `ON DELETE CASCADE` boundary cases. The file creates tables in the FK-safe order from ADR-006 § 6 (user → event → group → member → device → stage → set → artist → artist_source_ref → set_artist → pick → artist_cache → group_activity) and adds every index from ADR-006 § 3 (26 indexes total).

A `Settings` field `database_url` is added; `app/main.py` wires up a request-id middleware that puts `request_id: uuid4()` into the structlog context for every request.

## 4. Method signatures / new APIs

```python
# app/db/session.py
from collections.abc import AsyncGenerator
from sqlalchemy.ext.asyncio import (
    AsyncSession, async_sessionmaker, create_async_engine,
)

engine = create_async_engine(str(settings.database_url), echo=settings.echo_sql)
async_session_maker = async_sessionmaker(engine, expire_on_commit=False)


async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with async_session_maker() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

```python
# app/middleware/request_id.py
class RequestIdMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next: Callable[..., Awaitable[Response]]) -> Response:
        request_id = request.headers.get("x-request-id") or str(uuid7())
        with structlog.contextvars.bound_contextvars(request_id=request_id):
            response = await call_next(request)
            response.headers["x-request-id"] = request_id
            return response
```

## 5. Constants and thresholds

| Constant | Value | Rationale |
|---|---|---|
| `default` PK type | `uuid_utils.uuid7()` returning stdlib `uuid.UUID` | ADR-006 § 4.1; `uuid-utils` is the only mature Python UUIDv7 library as of 2026. |
| `TIMESTAMPTZ` everywhere | yes | ADR-006 § 4.2; absolute instants. |
| `JSONB` (not JSON) | yes | ADR-006 § 4.10; Postgres-from-start lets us index on shape later. |
| Alembic revision id format | `0001_v001_baseline` | NF-006 — readable; future migrations are `0002_*`, `0003_*`. |
| Connection pool min/max | 5 / 20 | Render's smallest Postgres tier limits us to ~22 connections; leaves headroom for migrations. |
| `expire_on_commit` | `False` | Standard for async sessions; avoids implicit refetch after commit. |

## 6. Edge cases enumerated

| Case | Expected behavior |
|---|---|
| Migration run on an empty database | Creates all 13 tables + 26 indexes. |
| Migration run twice on the same database | First run: success. Second run: `alembic upgrade head` is a no-op (head already current). |
| Migration interrupted mid-way (e.g. CI killed) | Alembic transaction rolls back; DB is back to the state before the migration started. Verified by `test_migration_idempotent`. |
| `Pydantic.PostgresDsn` parsed from a non-asyncpg URL (`postgresql://...`) | Settings validator coerces to `postgresql+asyncpg://...` so Alembic and SQLAlchemy share one URL. |
| Same-second UUIDv7 collision under high write load | Probability negligible; column is PK and the DB rejects duplicates anyway. Not a bug. |
| `created_at == updated_at` on insert | Yes — both use `func.now()` server-default. |
| Future migration that adds a column with `NOT NULL` and no default to `user` | Out of scope — that's a follow-up ticket's problem. |

**Manual QA:**

1. Spin up a local Postgres 16 via `docker run -p 5432:5432 -e POSTGRES_PASSWORD=dev postgres:16-alpine`.
2. `DATABASE_URL=postgresql+asyncpg://postgres:dev@localhost/postgres uv run alembic upgrade head`.
3. `psql postgresql://postgres:dev@localhost/postgres -c '\dt'` shows 13 tables.
4. `psql ... -c '\di'` shows 26 indexes (count via `\di+ | wc -l`).
5. `uv run uvicorn app.main:app` — server starts, no migrations needed at startup.

**Structured-log lines emitted on success:**

| Event | Fields | Trigger |
|---|---|---|
| `db.engine_created` | `pool_min`, `pool_max`, `echo_sql` | Engine creation at app boot. |
| `db.migration_complete` | `head_revision`, `tables_created` | After `alembic upgrade head` (logged by `alembic/env.py`). |

**Failure modes:**

- DB unreachable at startup → `asyncpg.exceptions.CannotConnectNowError` propagates from `engine.connect()`; FastAPI startup fails; uvicorn exits.
- Migration failure → Alembic rolls back the transaction; `alembic upgrade head` exits non-zero with the SQL error.

## 10. Rollback plan

`alembic downgrade base` drops all 13 tables. Then revert the PR — the SQLAlchemy models and session code disappear; BE-001's scaffold remains intact. No production data exists at this point so there's no data-loss risk. If a downstream PR has already merged that depends on the schema, revert that PR first, then this one.
